# 半角数字入力プラグイン

kintoneの「文字列（1行）」「数値」「リンク」フィールドに入力された値を、入力中にリアルタイムで半角数字（＋設定した許可記号）へ自動変換するプラグインです。

## 1. 機能概要

- 対象フィールド（文字列１行 / 数値 / リンク）で、全角数字・全角ハイフン類（－ ー ―）・全角ピリオド（．）を、入力の都度、半角に自動変換します。
- フィールドごとに許可する文字セットを以下の3種類から選択できます。
  - 数字のみ（`0-9`）
  - 数字とハイフン（`0-9`, `-`）
  - 数字・ハイフン・ピリオド（`0-9`, `-`, `.`）
- 許可文字セット以外の文字（全角変換後も残る文字）は自動的に除去されます。
- モバイル端末では `inputmode` 属性を付与し、数字用のキーパッド（テンキー）が表示されるよう誘導します。
- 設定でフィールドにフォーカスした際の枠線ハイライト表示のON/OFFを切り替えられます。

## 2. 制約事項（重要）

- **ブラウザのIME変換モードは、JavaScriptから直接制御するAPIが存在しません。** 「日本語入力を強制的にOFFにする」ことはできないため、本プラグインは「IMEモードを変更する」のではなく、「入力・変換確定後の値を必ず半角数字（＋許可記号）に補正する」方式を採用しています。
- 旧IE/Edge（EdgeHTML版）で使えた `ime-mode` CSSプロパティは、現行の主要ブラウザ（Chromium系Edge、Chrome、Safari、Firefox等）では無効化されており利用できません。そのため、そもそも「IMEを日本語入力不可にする」という手段自体が現行ブラウザには存在しません。
- 上記の理由により、ユーザーが日本語入力モードのまま全角数字を入力しても、変換確定・入力イベントのタイミングで半角に補正されます（入力中の一瞬だけ全角表示になる場合があります）。

## 3. 対応範囲外

- **サブテーブル内のフィールド**は対象外です（設定画面のフィールド候補にも表示されません）。
- **一覧画面のインライン編集**（`app.record.index.edit.show` 相当の画面）は対象外です。レコード追加画面・レコード編集画面（デスクトップ・モバイル双方）のみに対応します。
- `LINK` フィールドは電話番号・URL・メールアドレスなど数値以外の用途にも使われるため、数値専用運用でない場合は設定対象に含めないことを推奨します（設定画面にも注意書きを表示しています）。

## 4. インストール手順

1. 本プラグインをビルドして生成した `dist/plugin.zip` を用意します（ビルド方法は下記6章参照）。
2. kintoneシステム管理 → プラグイン → 「プラグインの追加」から `plugin.zip` をアップロードします。
3. 対象アプリの「アプリの設定」→「プラグイン」から本プラグインを追加します。

## 5. 設定方法

1. アプリのプラグイン設定画面を開きます。
2. 「＋ フィールドを追加」で行を追加し、対象フィールドと許可文字セットを選択します（複数フィールド設定可）。
   - フィールド候補は対象アプリの「文字列（1行）」「数値」「リンク」フィールドのみが表示されます（サブテーブル内フィールドは表示されません）。
3. 必要に応じて「対象フィールドにフォーカスした際、枠線で視覚的に強調表示する」を有効にします。
4. 「設定を保存」を押すと保存され、アプリの設定反映画面に戻ります。

バリデーション仕様:
- フィールド未選択の行は保存対象から除外されます（エラーにはなりません）。
- 有効な行（フィールドが選択された行）が1件もない場合はエラーになります。
- 同じフィールドを複数行で選択した場合はエラーになります。

## 6. ビルド方法

### 6.1 事前準備

```console
$ npm install
```

### 6.2 初回ビルド（秘密鍵がまだ無い場合）

kintoneプラグインは、プラグインIDを一意に識別するための秘密鍵（`.ppk`ファイル）で署名されます。秘密鍵を指定せずにビルドすると、ビルドの都度新しい秘密鍵とプラグインIDが自動生成されてしまうため、**初回ビルド時に生成された鍵を保存し、以後のビルドで再利用する**運用にしてください。

```console
$ npm run build:init
```

- `dist/plugin.zip` と、自動生成された秘密鍵（`dist/<自動生成ID>.ppk`）が生成されます。
- 生成された `.ppk` ファイルを、プロジェクトルートに `private.ppk` という名前でコピー（またはリネーム）してください。

```console
$ mv dist/*.ppk private.ppk
```

`private.ppk` は `.gitignore` で除外されているため、**Gitにはコミットされません**。紛失するとプラグインの更新時にプラグインIDが変わってしまう（＝別プラグイン扱いになる）ため、安全な場所に個別に保管してください。

### 6.3 2回目以降のビルド（秘密鍵を再利用する場合）

```console
$ npm run build
```

`private.ppk` を使ってビルドされるため、プラグインIDが変わらず、既存のプラグインをアップデートする形で反映できます。

### 6.4 補足

- `@kintone/plugin-packer` は現在メンテナンス終了（Deprecated）となっており、後継として `@kintone/cli`（`cli-kintone`）への移行が案内されています。ただし本プラグインの初期実装では、実績のある `@kintone/plugin-packer` をそのまま採用しています。将来的なビルド基盤の移行は別途検討してください。
- CLIの実際の使用方法は `kintone-plugin-packer [OPTIONS] PLUGIN_DIR` です。出力先パスは `--out` オプションで指定し、`PLUGIN_DIR`（本プロジェクトでは `src`）を最後の位置引数として渡します。`--ppk` を省略した場合、`--out` の出力先と同じディレクトリに `<生成されたプラグインID>.ppk` という名前で秘密鍵が自動生成されることを実機検証で確認済みです。
